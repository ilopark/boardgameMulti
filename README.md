# 보드게임 (티츄 · 스컬킹)

친구들이랑 하려고 만드는 실시간 웹 보드게임.

## 지금 상태

| 영역 | 상태 |
|---|---|
| 룰 스펙 (공식 룰북 검증) | ✅ [docs/RULES.md](docs/RULES.md) |
| 스컬킹 트릭 판정 · 점수 · 2인 유령룰 | ✅ 테스트 57개 |
| 티츄 조합 파서 · 되받아치기 | ✅ 테스트 26개 |
| 인원 | 티츄 4명 / 스컬킹 **2~6명** |
| 방 만들기 / 방코드 입장 / 자리 / 준비 | ✅ 동작 확인 |
| 무작위 첫 딜러 · 딜러 회전 · 선턴 계산 | ✅ 테스트 17개 |
| 재접속 (새로고침해도 자리 유지) | ✅ 동작 확인 |
| **게임 진행 상태머신** | ❌ 다음 단계 |
| 카드 UI | ❌ 다음 단계 |

## 실행

```bash
npm install
npm run dev
```

- 웹: http://localhost:5173
- 서버: http://localhost:3001 (헬스체크 `/health`)
- 같은 와이파이의 친구는 터미널에 찍히는 `Network:` 주소로 접속

```bash
npm test        # 룰 엔진 테스트
npm run typecheck
```

## 구조

```
packages/core/   순수 룰 엔진 — 서버·클라이언트 공용, 네트워크 의존 없음
  common/rng.ts     시드 기반 셔플 (테스트 재현 + 리플레이용)
  protocol.ts       소켓 이벤트 타입 (서버·웹 공용)
  skullking/        덱 · 트릭 판정 · 점수 · 판본별 옵션
  tichu/            덱 · 조합 파싱 · 되받아치기 판정
server/          Socket.IO — 방 관리, 상태의 유일한 주인
web/             Vite + React
docs/RULES.md    구현 계약서. 코드와 다르면 문서가 맞다.
```

## 설계 원칙

1. **룰은 순수 함수로.** `resolveTrick(plays, options)` 처럼 입력만 받아 결과를 낸다.
   네트워크·DB를 안 타서 테스트가 빠르고, 나중에 AI 봇도 같은 함수를 쓴다.
2. **서버가 상태의 주인.** 손패를 클라이언트에 전부 보내고 CSS로 가리는 짓은 안 한다.
   개발자도구 열면 다 보인다. 서버는 각자에게 자기가 볼 수 있는 것만 보낸다.
3. **판본·하우스룰은 옵션으로.** 스컬킹은 판본마다 보너스 점수가 다르다
   (인어→스컬킹: 2018판 50점 / 2021판 40점). 상수를 코드에 박지 않는다.
4. **룰 변경 순서는 문서 → 테스트 → 구현.** 반대로 하면 룰이 코드에 숨는다.
